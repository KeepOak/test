# Account greeting and sign-in expiry

Turning an account on in setup now sends one tools-free, 16-token greeting to that exact account. Setup says that the greeting consumes plan or paid allowance. The backend resolves an existing model in that account's pool, binds its exact account with existing owner/identity/address/disabled/cap checks, and does not fall back to another account. The reply names the actual preset and model, with Change the model opening existing Models Settings. Signing in through the account dialog also greets the completed account when setup's Models step is still open. Choose the model later still proceeds without choosing an account.

Account greetings retain network provider rules and existing account usage recording. They refuse a household, paired or short-lived-key caller through existing account checks, and stop when the app locks, Lockdown starts, the active profile changes or the transport disconnects. The completion has a thirty-second timeout. Existing identity reads may run before it; the timeout is not a total sign-in or billing guarantee. Leaving setup stops its browser request and ignores any stale result. Already sent work cannot be recalled.

The account dialog now expires first/extra ChatGPT waits at their actual `expiresAt`, Google waits at its returned OAuth duration, and coding assistant waits at the exact ten-minute deadline returned by the backend. It clears stale codes, stops the current flow through existing cancellation routes and offers retry. Poll responses are checked against the same owner/profile/token/dialog/plan before they update the window. A changed actor does not cancel a different actor's flow. Google cancellation uses the actual OAuth connection ID.

The engine now records a typed recovery marker when a direct owner model call cannot continue after its permitted retry/fallback/limit path. Known no-model, credential/entitlement, model-not-found, account-cap, exhausted service and stall classes qualify only before any output; budget, policy and partially streamed results do not. The local owner state exposes the marker only on a failed run. A newly submitted, still-visible owner turn can open Add an account or setup Models once, with token/profile/session/lock/dialog fences. Historical failed turns show recovery actions and never open dialogs by themselves. The marker describes this task’s permitted route, not proof every globally configured model failed. Legacy unclassified program/account errors retain their existing behavior, so this implementation does not interpret arbitrary provider error text. API-key account creation outside setup's enable/sign-in paths retains its existing behavior. Choosing Change opens the full Models page; it does not silently select another model.

Reference: [Hermes onboarding](https://github.com/NousResearch/hermes-agent/blob/a9a54245b2311c705d29050b7f9868c015917aec/apps/desktop/src/store/onboarding.ts), especially device expiry, authenticated model confirmation and credential-warning recovery. Its [MIT licence](https://github.com/NousResearch/hermes-agent/blob/a9a54245b2311c705d29050b7f9868c015917aec/LICENSE) was reviewed. This is an original implementation adapted to Branch's existing account/provider APIs; no upstream source was copied and no dependency was added.

Static source review and `git diff --check` only. No tests, builds, app execution, model requests or sign-ins were run. Provider/account interoperability, expiry timing, billing and UI behavior remain for review and testing. UP-UI-059 remains partial for legacy unclassified program/account errors; the structured configured-but-unavailable provider route and no-model recovery now exist.
