# Typed tool macros (RES193)

Settings > Developer > Typed tool macros opens the imported macro list, check/import editor and explicit run controls. The bounded `branch-tool-macro/1` JSON package contains a name, typed input fields, and up to 12 registered-tool steps. Values are text, number, yes/no, list of text or list of numbers. Arguments are scalar/list literals or structural `{ "$value": "field" }` references to inputs or earlier declared output fields. Unknown tools, forward/unknown references, overwritten values, unknown fields and packages over 64 KB fail before saving. Twenty imported macros are allowed. Remove uses an explicit confirmation and refuses unfinished runs until they are cancelled. Input/output/argument counts and literal sizes are bounded. Nothing is evaluated as JavaScript or a shell pipeline.

For example, the UI's supplied `files.glob` macro accepts `patterns` as `list of text`. Checking it runs no tools; importing creates an immutable saved graph flow and publishes it through the existing saved-flow catalogue. It does not start work. Run input `{ "patterns": ["src/**/*.ts"] }` calls the actual registered workspace glob tool with a real string array, retaining its own secret-file filtering. A literal `{name}` remains literal. Missing or wrongly typed inputs are rejected by the existing graph input schema; outputs are checked at each checkpoint and actual tool arguments by the registered tool's own schema at execution. No new tool registration or dependency is added.

The future run uses `Flows` and `FlowGraphRunner`, preserving the current owner's gate, the original retained source, Trunk permissions, inherited task restrictions, policy checks, approval fingerprints and checkpointed resume. It never grants permissions, looks up credentials, or adds an unchecked executor. Tool arguments and state are retained by existing flows; packages and input values must not carry credentials. Tools that need credentials should resolve them through their existing guarded service contract.

Approval/resume is bound to the exact run ID plus the displayed next node, question and node sequence. Stale questions are rejected. Interrupted steps show explicit retry or skip choices; their previous effects are not assumed. Macro definitions are immutable after import to avoid executing edited instructions from an old review; import a new package for changes. Existing graph-run cancellation now aborts the cooperative tool/runtime signal, ends the actual checkpoint as cancelled and prevents later steps or resume. Abort reaches map/subflow/prompt paths too. It cannot reverse completed effects or force an uncooperative tool to stop.

HTTP: GET/POST `/api/flows/macros`, POST `/api/flows/macros/check`, existing POST `/api/flows/<id>/run`, GET `/api/flows/runs/<id>`, and POST `/api/flows/runs/<id>/cancel|resume`. The usual owner-only orchestration route and global lock/short-lived-key/action gates apply. UI async responses fence profile/token, dialog and generation, and existing modal keyboard controls are reused. The list can be reopened later; saved graph flows can also be run through their existing published tool.

Source comparison: OpenClaw's Lobster tool separates run/resume and an explicit approval choice, accepting structured arguments instead of requiring a conversation for each invocation. Remaining gaps: packaged autonomous Hands/event bindings and RES194 unified cron/webhook/MQTT/device SOP objects remain unimplemented here. Existing SelfStarting procedures already provide clock/task starts and approval/resume, and are not replaced. New macro UI is English and technical; general expression templates, nested object arguments, conditionals and dynamic tool names are intentionally absent. Developer strings need localisation. Source review and git diff --check only; no tests, builds, browser/native/runtime, provider/model, database or credential execution in this session. Runtime and UI behavior remain unverified.
