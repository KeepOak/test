# Team turns without an unrestricted primary run

RES-220 concerns an extra full agent run before a team starts. The frozen source still called `runtime.run()` in `Teams.startParent`, then created a new context after that parent had finished. A prompt could therefore run tools before any specialist, and the subsequent fanout lost the parent's actual cancellation signal and narrowed reach.

Teams now use `Runtime.runTeam`: the existing recorded run startup, origin marks, session scope, project scope, inlet checks, monthly budget, native cancellation, shared budget/deadline, cleanup and settlement remain. A trusted in-process callback replaces the primary model/tool loop. There is no new provider adapter, synthetic run state or second agent answering first. The orchestration parent also skips its own advisory/review/reflection model jobs; member runs retain their existing behavior.

The callback passes the actual live context to the existing specialist fanout. Every saved member permission is checked against that context before members start. An incompatible member refuses the turn rather than gaining new reach. Original signed-in key/profile/caller marks and tool policy, role, sandbox and grant enforcement remain on the member execution path. The team request's source identity still scopes its idempotency claim; it is not reinterpreted as an owner policy source or accepted from a new request field.

Native Stop reaches child signals. Pause and owner/live-parent changes are checked before and after each batch. A Pause stops further dispatch and leaves reconciliation to the existing team task workflow; this change does not promise resumable partial fanout. The real parent deadline bounds the whole orchestration. Concurrent partial effects and unknown member outcomes retain the existing need for reconciliation, never an automatic replay.

Answers are recorded on the claimed team task before its parent settles, then written with the existing atomic room/task completion only after a completed parent. Parent cleanup failure is therefore reported for reconciliation. A deleted room/member conversation remains governed by the existing answer-deletion checks. Stale claims never execute a new turn.

`run.started.teamOrchestration` marks the parent before member work. Generic continuation/resume refuses this marker. Restart recovery settles the interrupted parent for team reconciliation rather than starting a primary agent or replaying the fanout. Member-run recovery continues to use its original recorded source/grants and existing recovery policy.
