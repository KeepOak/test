# Sandboxed contribution slots and reply canvases

Plugin page contributions are plain data in `BranchPlugin.uiPages`, separate from #1180's plain badges, labels and draft buttons. The host supports the named `conversation-aside` and `composer-aside` slots. Every page has a plugin-local id, an existing owner session UUID, title and HTML. The loader namespaces ids, accepts at most eight 40 KB pages per plugin, isolates malformed/duplicate entries, and registers only pages covered by the owner's `ui.contribute` manifest grant. Disabling or unloading a plugin drops its registrations. The host checks live enablement, grant, owner and session again when listing and serving pages.

Each contribution renders in its own iframe with `sandbox=""`, using the existing `mcp-apps` sanitization and no-script response CSP. Its title and load/error/timeout fallback belong to the host; no plugin rendering callbacks run in the window. Only twelve contributions are shown per session. A failed page gets its own fallback and does not replace another contribution. Network, forms, scripts, popups and browser permissions remain unavailable. This isolates displayed content; an enabled in-process plugin retains its existing trusted-code authority, and this patch does not turn that loader into a security boundary. Walled plugin forwarding of `uiPages` is not implemented.

Saved assistant replies containing a fenced `html` block get **Open reply canvas**. The owner first sees that exact persisted reply in the existing no-script renderer. **Run isolated scripts** is a separate native confirmation for that saved reply. The host then re-reads the owned message, binds a five-minute capability to its content hash, and loads the same trusted opaque proxy used by #1173 into a second opaque inner sandbox. It pins the proxy window and nonce for the one resource-ready exchange, then removes the listener. The canvas has no host/tool bridge: child messages are ignored. Inline scripts may update their own DOM and respond to local input, with no access to Branch, files, tools, network, storage or privileged browser permissions. External scripts and unsafe eval remain blocked.

The canvas uses the first supported HTML block, capped at 200 KB. It is a local reply surface, not an implementation of OpenClaw paired-node present/hide/navigate commands, A2UI actions, remote navigation or an automatic agent-controlled window. Closing removes its frame, revokes its capability and listener, and session/profile/view/lock changes close open canvases. Five-minute expiry removes an active frame. Owner-only local long-lived requests are required; household, short-lived-key, shared-door, App lock and Lockdown access are refused. CSP is a browser content boundary, not a CPU execution quota.

UI pages are held only in bounded process memory, at most 64 active capabilities, and are revalidated against current plugin/reply content when fetched. Static page leases permit reload; scripted proxy addresses are one-use. The main window's CSP and the default no-script MCP renderer are unchanged. Modern MCP 2026 SDK integration belongs to the separate lane; #1173's standalone proxy source is reused identically without modifying its Apps bridge or owner tool approval path.

Source comparison was read from [Hermes loader's explicit security boundary note](https://github.com/NousResearch/hermes-agent/blob/a9a54245b2311c705d29050b7f9868c015917aec/apps/desktop/src/contrib/runtime-loader.ts) and [per-contribution Slot boundary](https://github.com/NousResearch/hermes-agent/blob/a9a54245b2311c705d29050b7f9868c015917aec/apps/desktop/src/contrib/react/slot.tsx), plus [OpenClaw's Canvas entry](https://github.com/openclaw/openclaw/blob/f3672acef86233c56869829300a84d17621812c0/extensions/canvas/index.ts) and [widget panel document](https://github.com/openclaw/openclaw/blob/f3672acef86233c56869829300a84d17621812c0/docs/platforms/mac/canvas.md). Their MIT licences were read. This is an independent implementation, not a copy of their renderer loader, and adds no dependency.

Validation is source/diff review and `git diff --check` only. Tests/builds/app/runtime/browser/models/providers/DB/credentials were forbidden by owner instruction. CSP behavior, actual iframe placement, plugin lifecycle and end-to-end rendering remain unverified before release.
