# Google Docs and ClickUp writes

Google account cards now have a separate Docs write opt-in. Save it and sign in again: existing read-only grants cannot edit. The official `documents` scope is checked against this account's saved grant; account routing uses the existing per-account async binding and requires an explicit account id for writes when several accounts exist.

`gdocs.inspect` returns the chosen document's title, revision and tab ids. `gdocs.append` appends at the end of one tab; `gdocs.replace_text` replaces every literal case-sensitive match in that tab (empty replacement deletes matches). Both show the exact document/tab/revision/text arguments in the existing one-time owner approval, check the current revision/tab, and send Google `documents.batchUpdate` with `requiredRevisionId`. Changed revisions are rejected. Text is capped at 8,000 characters, matches at 1,000, tab metadata at 100 results. No arbitrary batch requests, formatting, document deletion, Sheets or Notion support is added. The response is provider acknowledgement, not independent read-back verification.

ClickUp already has the official `https://mcp.clickup.com/mcp` catalogue entry and real MCP discovery/call path. This change reuses that authentication, schema validation, per-tool permissions, error handling and receipts. Only that exact endpoint receives host-owned provenance and an exact remote tool/arguments target. Calls through this door are owner-window only and require one-time confirmation even in Full Access. Ambiguous operations are held without trusting remote readOnlyHint; this deliberately also prompts for reads. Tool arguments exceeding 16 KiB cannot form a preview. There is no guessed tool-name facade or duplicate native token storage. Operations supported are those actually discovered and owner-vetted from the official connection; remote tool availability is not certified by this source-only delivery. Arbitrary endpoints and third-party ClickUp wrappers are not covered by this endpoint-specific gate.

Existing transaction/approval and tool receipt paths remain the consumers. No model-provided approval boolean bypass is introduced. Raw developer tool execution outside Runtime policy is not a substitute for owner approval; live MCP Apps/workbench end-to-end checks remain outstanding.
