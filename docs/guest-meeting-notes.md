# Opt-in guest meeting notes

RES-123 now has a concrete prepared-provider path through Recall.ai v1 for Google Meet, Teams and Zoom. It builds on #1226's private editable notes and one-use Google Docs export; it does not operate a local browser bot or infer calendar invitations. Default state is off and every join is manually reviewed.

The owner supplies an exact HTTPS platform URL, purpose, 1–120 recording minutes, Recall region, named locker references for API and workspace verification secrets, and a stable public callback origin. No raw credential is saved or shown. Preview pins those values, visible bot name, participant notice and unknown-price warning into a ten-minute one-use grant. The owner configures the exact preview callback URL in Recall's lifecycle webhook dashboard and confirms it is reachable before approving join. No tunnel, install or provider configuration is automated.

Create Bot sends `recording_config:null`; the guest enters without capturing recording data. Join/new-participant chat notices disclose the purpose and need for consent. Admission and notice delivery are subject to platform controls. The app waits for a verified `bot.in_call_not_recording` event, then requires a separate owner press confirming that the notice is visible, every participant has consented, and the owner will monitor late arrivals. Only then does Start Recording configure English low-latency transcription and signed `transcript.data` delivery. Consent attestations are made by the owner; chat notices do not prove consent. The owner must press Leave on objection or an unconsented arrival. There is no automatic speech/chat consent detector. This increment does not support unattended meetings.

Provider automatic-leave limits are 120 seconds waiting room, 120 seconds with no other participant, 180 seconds while not recording, the approved recording minutes, and 30 seconds on denied recording permission. Recording minutes are not an overall wall-clock deadline or verified spending cap. The owner sees this distinction before join. Provider charges, retention, admission and automatic-leave enforcement remain unverified locally.

The unauthenticated public callback accepts only a previously approved random session ID. It bounds raw bodies to 64KB, verifies Recall's workspace HMAC with a five-minute timestamp window before JSON parsing, binds signed bot metadata/ID to the grant and suppresses recent duplicate events. Lifecycle updates drive actual status; local Refresh reads saved events and never polls the provider. Signed utterances provide bounded live notes (first 6,000 characters). Speaker names/text are untrusted and escaped. Raw media URLs and attendee email addresses are not consumed. No model summary or automatic disclosure occurs.

Session IDs, secret references, purpose, URL, status, recent event IDs and bounded transcript text are stored in the owner's settings so a restart still exposes Leave and notes. Sixteen sessions are kept; terminal sessions can be evicted to admit another. Unknown join outcomes remain visible for provider-dashboard recovery; create/record requests are never automatically retried. A recording request is consumed before sending to prevent duplicate recording on an ambiguous result. Leave is an explicit owner operation and acknowledgement does not claim the bot has left until a lifecycle event arrives.

An owner press snapshots verified live text into #1226's private editor. A further exact Google account/document/tab/revision/text preview and one-use approval append to Docs. The owner must check document readers. No inferred attendee emails, automatic mail, calendar autojoin, guaranteed provider admission, automatic participant-consent monitoring, automatic summary or full post-meeting transcript download are provided. English live excerpts and host-monitored consent are the supported path. Existing transcript-only historical workflow remains available.

All external sends recheck owner/profile/caller/app-lock/Lockdown restrictions across secret awaits. Provider requests use Branch's existing guarded fetch/network policy, fixed Recall region hosts, no redirects and bounded response reads. Signed inbound events may arrive while the window is locked; they cannot invoke models, join, record, export or change configuration. Legacy pre-December-2025 Recall accounts with separate lifecycle and realtime secrets require consolidation/new workspace; this path uses one workspace verification secret and fails closed otherwise.

Stack: #1226 -> #1213 -> #1142. Narrow integrations are personal construction, meeting-note draft provenance, public signature-verified callback, owner-window HTTP actions, composer menu/settings entries and form initialization. No MCP/runtime edits or dependency additions. Source review and diff checks only: no app, browser, meeting, provider, model, database, credential, build or test execution.
