# KeepOak account connection

Settings → Accounts offers an owner-only Enable action. Enabling stores a local flag and makes no network request. Connect requests only the `profile` scope, displays the returned code and an activation link, and polls while its dialog is open. The server also enforces the polling interval, expiry and single concurrent request, so repeated UI requests cannot poll faster. Locking or closing Branch forgets pending device codes.

The connection uses the fixed HTTPS origin `https://keepoak.com`, client `branch-desktop`, and `/oauth/device/code`, `/oauth/token`, `/oauth/revoke`, `/api/v1/me`. Redirects are refused. A returned activation shortcut must name the exact activation page and matching user code. Device authorization follows [RFC 8628](https://www.rfc-editor.org/rfc/rfc8628), including `authorization_pending`, `slow_down`, expiry and timeout backoff. Revocation uses [RFC 7009](https://www.rfc-editor.org/rfc/rfc7009) form parameters.

Access and rotating refresh tokens stay in the owner's default locker. The status route returns metadata and the displayed user code, never the device code or account tokens. Read profile is an explicit owner action, renews expired tokens, and retries one unauthorized profile response once after renewal. Temporary failures preserve the saved connection. Disconnect revokes refresh and access tokens before removing the local connection keys and disabling the flag. It deletes no account data, conversations, memory or files.

The engine routes are `GET /api/keepoak` and empty-body `POST /api/keepoak/{enable,begin,poll,cancel,profile,disconnect}`. Every route requires the owner, an unlocked app and a full app-window credential. Owner, lock, cancellation and network policy are checked again around asynchronous operations, including immediately before the guarded sender connects. There are no model tools for these actions.

This source implementation has no live-service acceptance evidence. The server must implement the documented device response, bearer tokens with rotating refresh tokens, profile shape and revocation endpoints. No staging configuration or credentials are bundled. Cloud computers, relay, workspace actions, look sync and backup remain unavailable; their existing controls keep their current availability. The request omits a device-name parameter because its wire name has not been specified. A pending device grant left by closing only the dialog expires at the server; Branch makes no further polls. A failed or partially confirmed revoke retains the local connection for an owner retry.
