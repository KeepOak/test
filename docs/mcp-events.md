# Owner-configured MCP event automations

The source form in this window adds a modern HTTP source through the existing owner server gateway, with a credential **environment variable name** rather than a secret value. Its initial discovery uses the actual modern SDK, then the existing reviewed version and original hashed tool-policy filtering. Existing sources configured for `auto` retain side-effect-free legacy negotiation fallback; Events requires actual modern negotiation. This path requires an existing tool server with at least one permitted tool; event-only servers and stdio event sources are not supported.

Branch acts as an MCP Events **client** for the draft webhook-only contract. It uses the existing modern SDK HTTP transport and real `2026-07-28` negotiation, pinned server version, network policy, and explicit schemas for `events/list`, `events/subscribe`, and `events/unsubscribe`. Core SDK 2.2.0 strips the draft `events` capability, so the client performs an explicit-schema `server/discover` request to check that actual capability. It does not advertise a Branch Events server or substitute the core `subscriptions/listen` stream.

In the local unlocked owner window, open **Event automations**. Add an enabled, reviewed HTTP MCP server configured for `stateless-preview` or `auto`, and create the desired automation with the existing trigger controls. Set the HTTPS callback origin of the owner's relay or tunnel. That service must forward `/webhooks/mcp-events/*`, exact body bytes, `Content-Type`, `webhook-id`, `webhook-timestamp`, `webhook-signature`, and `X-MCP-Subscription-Id` to Branch. Neither this form nor startup provisions or starts a relay/tunnel. Expose only the callback door, never the owner management API. Reachability and relay authentication require deployment verification by the owner.

Load the server's event catalog, choose an event, enter schema-valid filter arguments, select the automation, and explicitly check that these events may start it while the owner is away. Subscription creation supplies a newly generated 32-byte `whsec_` key and callback URL. A fresh signed verification challenge must be received and echoed before activation; its subscription header must match the server's returned ID. Subscriptions and secrets are held in the existing owner-scoped local store and persist across restarts. Keys never appear in the state API, window or delivery receipts. They are not encrypted separately from the existing store, so its backup/access protections apply.

Refresh before the displayed expiry using the owner control. Refresh repeats the exact event, arguments, callback, and secret; it rechecks the event definition, source and trigger. The server must grant a finite lifetime of at most approximately one hour. There is no background reconnect, refresh, stdio program launch or autonomous setup. Stop closes local admission first and requests upstream unsubscribe. Failed upstream cleanup is reported separately; local admission stays stopped. Forget removes a stopped local record, including its key; an unreachable upstream may retain its subscription until expiry.

Every callback verifies Standard Webhooks symmetric **v1 HMAC-SHA256** over `webhook-id.webhook-timestamp.<exact body bytes>`. It rejects duplicate/ambiguous headers, malformed keys and signatures, timestamps outside five minutes, mismatched body/header event IDs, names, subscription IDs, unsupported control envelopes, invalid payload schemas and excessive nesting. Multiple space-separated v1 signatures are accepted for sender rotation; asymmetric `v1a` and receiver key rotation are not implemented. The envelope is limited to 256 KiB, event data to 16 KiB and filter arguments to 8 KiB. Schemas are object schemas limited to 32 KiB and depth 16; external references and regex-based keywords are refused. Catalogs have ten pages and 256 entries, with no duplicate event names.

Admission rechecks the active owner profile, app lock, Lockdown, enabled source, pinned version/launch/auth fingerprint, current network/approval-policy fingerprint, unchanged enabled trigger, callback origin and expiry. A policy/source/automation edit requires stopping and reviewing a new subscription. Existing trigger rate, Trunk pause, runtime source, permissions and tool approval controls remain in force. Received content is wrapped as `mcpEvent.data` with source identity and an untrusted marker; it cannot configure another automation or restore old approvals. Automation templates should treat it as external data.

The persisted replay ledger claims each webhook ID **before** attempting the automation. A `2xx` acknowledges this admission, not a successful run. Duplicate retries receive an acknowledgment without another run. A crash between claim and start, or an ambiguous failed attempt, is not automatically retried; this deliberately trades recovery for avoiding duplicate effects. Failures are recorded through the trigger log. The ledger retains up to 2,048 IDs per subscription for 24 hours and refuses saturation. At most 24 subscriptions, four MCP control connections, four admitted runs, eight payload validations and eight callback body reads are allowed; callbacks are also limited to 120 requests per minute per socket peer with a bounded peer map. A shared relay peer shares that quota.

Webhook arrivals may be out of order. Branch does not advance a cumulative replay cursor from individual arrivals; explicit refresh uses the last server-granted cursor with a five-minute replay age ceiling. No cursor or replay support is fabricated. `truncated` is shown to the owner. Polling, push, gap/terminated controls, indefinite subscriptions, batching and full recovery guarantees are outside this implementation.

Contracts consulted: [draft MCP Events design](https://github.com/modelcontextprotocol/experimental-ext-triggers-events/blob/main/docs/design-sketch-proposal.md), [OpenAI webhook-only profile](https://developers.openai.com/plugins/build/mcp-events), [Standard Webhooks 1.0](https://github.com/standard-webhooks/standard-webhooks/blob/main/spec/standard-webhooks.md). Both upstream design documents are Apache-2.0 licensed; this implementation is original and copies no upstream source. It reuses the already declared MCP SDK dependencies and preserves their packaged license notice.

Source inspection and `git diff --check` are the validation boundary for this draft. No tests, builds, runtime, provider, model, database, credential or live callback/relay execution was performed. Live signature vectors, full subscription interoperability, native-window behavior and deployment exposure remain unverified.
