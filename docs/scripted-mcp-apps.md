# Interactive MCP pages

MCP pages remain script-free by default. The owner can enable Apps negotiation for a server in **Server pages**, reconnect it, then approve an individual saved `ui://` page. Tools declaring the Apps resource URI have that exact HTML resource read from the same authorized connection after their normal tool result. Resource reads are bounded to 40 KB and the combined result to 60 KB. Tool visibility distinguishes model and app callers; app-only tools are excluded from model descriptions and rejected for ordinary callers.

Interactive HTML runs in an inner opaque sandbox inside a trusted, CSP-sandboxed proxy. The host pins the proxy window and a per-page nonce, and the proxy pins the inner window. Server code is never evaluated in the owner window. Both frames deny network, forms, popups, nested server frames, and privileged browser permissions. Only inline scripts/styles and data images are supported. External scripts, storage, network domains and requested camera/microphone permissions are unavailable in this bounded offline profile. The existing script-free renderer and main-window CSP remain unchanged.

The Apps 2026-01-26 initialization/input/result messages and `ping` are implemented. `tools/call` proposals are limited to the original MCP server, tools visible to apps, and the original saved run's permission set. A separate native owner confirmation approves immutable inputs in a one-use, 30-second ticket. The runtime's normal owner execution gate still applies. Capabilities expire after five minutes; requests are bounded to 20 per minute, bridge messages to 60 per minute, and pages to eight. Closing a page or disabling its server revokes outstanding capabilities and signals cancellation to active calls. Cancellation cannot reverse a remote side effect already performed.

Only local owner windows with long-lived access can open these pages. Short-lived keys, shared-door access, non-owner profiles and lockdown are rejected. The host does not advertise unsupported Apps resource, link-opening, context-update or model-sampling features.

The legacy MCP server recognizes 2025-11-25 and reports its actual supported versions and sharing-dependent capabilities through `server/discover`. Full MCP 2026-07-28 support is outside this patch: its stateless execution/MRTR/subscription work is a separate prerequisite. Form elicitation is supplied by PR #1154; named artifact slots are separate. Accordingly UP-DOTS-007 remains partial until those protocol prerequisites are integrated.

Protocol references: [official Apps specification](https://github.com/modelcontextprotocol/ext-apps/blob/82221c0c8ce7661efa6771c9d461511b1650495f/specification/2026-01-26/apps.mdx), [MCP 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25), and [official 2026 server discovery](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/046fa30efd374370afb87ef830bd788eac5f217e/docs/specification/2026-07-28/server/discover.mdx). The source and license were reviewed for protocol comparison; this implementation is independent and adds no dependency or copied implementation.

Validation is source and diff review only. Tests, builds, browser/runtime runs, model/provider calls and credential/DB operations were deferred by owner instruction. Browser CSP behavior and end-to-end Apps compatibility still require validation before release.
