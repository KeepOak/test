# One personal main thread

Settings → Chat apps → One personal main thread lets the desktop owner explicitly share the exact current default Trunk conversation with one approved, named owner Telegram account. The confirmation identifies the account and session IDs, explains that its history becomes visible through that account, and requests the Branch PIN when configured. Full-owner-chat access must already be enabled; this setting grants no additional tool permissions.

Open the default Trunk and send a message there first, then review sharing. **Open main thread** opens the exact bound conversation with the existing window chat facility. Ordinary Telegram messages resolve to that same session after the original channel admission checks. Window messages continue through the existing profile/source/run guards; Telegram messages retain their original owner-chat source marks and execution checks. Neither surface adopts another person's thread or chooses a session by its title.

The prior Telegram conversation and history are preserved separately. Stopping sharing returns Telegram to its prior pointer. `/new` requires disconnecting sharing in the owner window first. No conversation, approval, model state or old history is copied or merged. Sharing does not broadcast unrelated window turns to Telegram: Telegram receives replies to its own turns, while the window can open the full shared history.

An account removal, sender block, App Lock, Lockdown, disabled full-owner-chat access, deleted session or changed default Trunk holds Telegram routing without falling back to the shared session through an old pointer. Caught-up messages, groups and other senders cannot enter it. Existing link operations cannot add another chat while sharing is enabled. A run marker prevents a late completed Telegram turn from replacing the prior pointer after sharing is disabled.

Normal message turns from the window and Telegram share an admission guard; an overlapping turn is refused instead of mixing steering. Existing approval continuation and slash-command controls retain their own original task guards. Other window conversations and all other Telegram chats remain separate. The opt-in is a profile-owner setting, not an automatic startup migration.

This builds on Branch's existing default-Trunk and per-chat thread implementation from #571/#726; those records already exist and are not duplicated. The adapter and permission checks are original Branch code using its existing Store, channel router and chat UI. No upstream code or additional dependency is introduced. Source review does not establish authenticated channel delivery or end-to-end behavior; no channel, runtime, database, test or build execution was performed for this delivery.

The research reference is OpenClaw's [Telegram DM session-key source](https://github.com/openclaw/openclaw/blob/main/extensions/telegram/src/dm-session-key.ts), which distinguishes a main DM scope from isolated account/peer routing. Its [MIT license](https://github.com/openclaw/openclaw/blob/main/LICENSE) was inspected. This implementation adapts the idea to Branch's existing exact owner identity and Trunk records; it does not copy or install OpenClaw code.
