# Owner chat policy commands

CHAT-206: `/allowlist` or `/allowlist list` reads rules for the source connection (including applicable global rules). `/allowlist allow|block|remove <exact sender ID>` requests replacement/removal of rules for that one sender and current connection. Wildcards, other connections, owner-identity changes and changes to the requesting owner's own admission are not accepted. Admission writes require explicit local owner confirmation in Settings → Chat apps → Chat policy requests within two minutes. The request expires on policy snapshot changes, source owner authorization changes, disconnect, App lock or Lockdown. The native window rejects short-lived keys and remote doors, and rechecks owner profile after reading the request body. Broader block rules still win; removal does not revoke pairing or other rules. Tool permissions and owner identity remain separate.

`/send on|off` changes output only for the source direct chat. Only a live, unedited text message from an exactly named owner on a server-vouched transport, with ordinary source admission and no App lock/Lockdown, may change it. Off takes effect after its acknowledgement; already dispatched provider requests cannot be recalled. Off guards actual adapter send, voice, buttons, typing, reaction, status, edit, deletion, file and picture methods. New ordinary inbound messages to that chat are ignored. Queued deliveries wait without consuming attempts and may resume after on; output gates are checked again at each transport invocation. This does not override platform pause, Lockdown, sender admission, outbound privacy checks or model/tool permissions. It persists across reconnect/restart. The named owner can resume with `/send on` while other gates permit that source; a paused platform can also be resumed locally. Other chats are unchanged.

CHAT-207 delivered coverage:

- `/footer [on|off]` uses the existing chat usage-footer implementation; no model call.
- `/export-session` exports retained user/assistant messages from only the current authorized owner DM as redacted Markdown. System/tool/internal Branch messages are excluded. More than 40 retained rows or an export longer than the lesser of 3,000 characters and the transport limit is refused with the existing local `/export` path. No arbitrary session IDs, files, tools or credentials are read. Source authorization and current-session identity are checked again after the outbound guard.
- `/models` already resolves to the real model picker/list through `/model`; retained unchanged.

`/review`, `/refine`, `/moa`, `/reload-mcp`, `/reload-skills` and `/login` are not advertised as implemented. Reviewer/task refinement and multi-model deliberation require their own task semantics; reload commands require actual lifecycle backends, and login requires a native credential flow. This change adds no dummy handlers or extra model requests. Replay suppression for these owner policy commands is bounded to 1,000 identities in memory; caught-up commands are ignored. Sender requests are rate-limited to one per sender per minute, at most eight pending and twenty recent requesters.

Prerequisites preserved: #1215 desktop shell control, #1191 local device pairing proposals, #1194 local diagnostics, and #1211 Telegram depth readout. The latter source commits are included on the #1215 stack without reinterpreting their authority.

No upstream code copied. Verification is source review and `git diff --check`; no tests, builds, apps, runtime, model, provider, database or credential operations were run.
