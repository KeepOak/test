# Owner chat policy commands

CHAT-206: `/allowlist` or `/allowlist list` reads rules for the source connection (including applicable global rules). `/allowlist allow|block|remove <exact sender ID>` requests replacement/removal of rules for that one sender and current connection. Wildcards, other connections, owner-identity changes and changes to the requesting owner's own admission are not accepted. Admission writes require explicit local owner confirmation in Settings → Chat apps → Chat policy requests within two minutes. The request expires on policy snapshot changes, source owner authorization changes, disconnect, App lock or Lockdown. The native window rejects short-lived keys and remote doors, and rechecks owner profile after reading the request body. Broader block rules still win; removal does not revoke pairing or other rules. Tool permissions and owner identity remain separate.

`/send on|off` changes output only for the source direct chat. Only a live, unedited text message from an exactly named owner on a server-vouched transport, with ordinary source admission and no App lock/Lockdown, may change it. Off takes effect after its acknowledgement; already dispatched provider requests cannot be recalled. Off guards actual adapter send, voice, buttons, typing, reaction, status, edit, deletion, file and picture methods. New ordinary inbound messages to that chat are ignored. Queued deliveries wait without consuming attempts and may resume after on; output gates are checked again at each transport invocation. This does not override platform pause, Lockdown, sender admission, outbound privacy checks or model/tool permissions. It persists across reconnect/restart. The named owner can resume with `/send on` while other gates permit that source; a paused platform can also be resumed locally. Other chats are unchanged.

CHAT-207 delivered coverage:

- `/footer [on|off]` uses the existing chat usage-footer implementation; no model call.
- `/export-session` exports retained user/assistant messages from only the current authorized owner DM as redacted Markdown. System/tool/internal Branch messages are excluded. More than 40 retained rows or an export longer than the lesser of 3,000 characters and the transport limit is refused with the existing local `/export` path. No arbitrary session IDs, files, tools or credentials are read. Source authorization and current-session identity are checked again after the outbound guard.
- `/models` already resolves to the real model picker/list through `/model`; retained unchanged.

The remaining six commands have these explicit backend scopes:

- `/review [focus]` critiques the latest completed answer; `/refine <feedback>` rewrites it. Both are new isolated, channel-source Runtime tasks with no tools, memory, project instructions or skill documents. They process only bounded quoted request/answer data (4,000/8,000 characters) and feedback (2,000 characters). They do not scan a repository or claim tests were run. A changed source conversation or completed answer suppresses delivery.
- `/moa <configured mixture preset ID> <question>` uses the existing owner-configured MixtureProvider, without creating mixtures or changing any conversation's saved model. The existing reference calls and writer report aggregate usage. The command warns that several calls cost more. The question is capped at 4,000 characters; no tools or private context are provided. Reference limits remain those the owner set on the mixture; the task reports summed usage against its budget, so this is not a strict pre-call dollar cap.
- Answer helpers have a two-minute deadline, two-step/8,000-token task budget and at most two concurrent helpers, one per chat. They refuse a busy chat. `/stop` cancels the current helper, and shutdown cancels and waits for them. No model call runs merely to list mixtures or open a native proposal.
- `/reload-skills` explicitly refreshes the current running chat task's governed active skill-version catalog and queues a named-sender note to load the current versions. It requires the original task's `skills.read` permission, activates no drafts and adds no permissions. Already-loaded earlier documents are not deleted from history. With no active task, new tasks already read a fresh catalog, and the command says so honestly.
- `/reload-mcp <server ID>` requests one enabled owner-managed server, not launch-file servers. Native confirmation binds the saved entry and source authorization; busy/opening connections are refused, and new acquisitions are excluded through the close/restart transition. The own-server generation fence prevents overwrite of a newer lifecycle action. Reopening uses the existing HTTP network policy or stdio launch approval; stdio may need another explicit native approval. Failure/cancellation can leave the server disconnected or off. This does not refresh launch-file definitions or silently approve changed tool permissions.
- `/login chatgpt|codex|claude-code` requests native sign-in selection only. The confirmed local window opens the existing account wizard for that provider; its ordinary Continue/Sign in controls start the actual device/program flow, with its existing cancellation/status handling. Login codes, links and tokens never return to chat. Existing accounts are not silently replaced, and other providers are not offered by this command. Native selection uses root's `openChatRequestedSignIn` seam, source commit `d624fe168a3678a6047fcf998fdea0fdf88e0ccf`.

All six commands require a live, exactly named owner DM on a vouched admitted transport, no voice/edit/attachments/backlog, and no App lock, Lockdown, platform pause or disabled chat output. Native requests expire after two minutes or source/configuration changes and have eight-pending/twenty-recent bounds with a one-minute sender rate limit. Replay suppression for owner policy commands is bounded to 1,000 identities in memory; caught-up commands are ignored. Helper results pass the privacy guard and fresh source/session checks before the original chat receives a bounded excerpt; full results remain in Branch. Native lifecycle/sign-in results stay local.

Prerequisites preserved: #1215 desktop shell control, #1191 local device pairing proposals, #1194 local diagnostics, and #1211 Telegram depth readout. The latter source commits are included on the #1215 stack without reinterpreting their authority.
