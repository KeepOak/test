# Trunks in one Telegram group

CHAT-076: the local owner can bind an exact configured Telegram connection and negative group ID to a fresh room with two to six existing Trunks, in Settings → Chat apps → Trunks in a Telegram group. A disabled binding may be replaced by another fresh room without deleting its earlier conversations.

The existing group activation policy, platform pause, sender admission, app lock, lockdown, and each member's channel reach apply. An exact configured @handle can satisfy mention activation. Text addressed to members selects those members; otherwise an admitted message goes to every configured member. No broadening of sender permissions or owner authority occurs. The runner does not call the native-owner room send API: each member uses its fresh conversation with `source: channel`, ordinary group permissions, and exact source provenance recorded on the run.

Two members run concurrently, at most four groups are active, and each member has a two-minute runtime deadline. Optional owner-enabled handoff admits one extra round, only to at most two other members named in the first replies. Quoted replies are untrusted data. Membership, mapping, admission, activation, platform policy, and member reach are rechecked before work and delivery. Disabling a mapping cancels its active runs; shutdown waits for in-flight work to settle. Replay suppression is bounded to 1,000 message IDs in memory, so it does not survive restart; caught-up, edited, voice, and attachment messages are refused for rooms.

UI-266 is partial: setup displays each member's name, handle, enabled state, handoff setting, and actual execution host (`This Branch engine`). All messages use the one configured Telegram bot account, prefixed by the member name. This does not implement separate bot identities, a remote-computer roster, an inline Telegram bot rail, or a shared native room event transcript. Member task histories remain available in Branch. Waiting tasks require review in Branch; group messages cannot approve them.

Source contract reference: [OpenClaw broadcast groups](https://github.com/openclaw/openclaw/blob/main/docs/channels/broadcast-groups.md), read together with its [MIT license](https://github.com/openclaw/openclaw/blob/main/LICENSE). The implementation uses Branch's existing router/runtime/rooms interfaces; no upstream source code was copied. Telegram delivery reuses the existing Branch adapter and its configured credential transport. This change is source-only: no tests, builds, application, provider, model, or credential operations were run.
