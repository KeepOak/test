# Continue on another Branch computer

The computer menu has **Keep working on another computer**. Pair an existing Branch engine, enable Other computers on both engines, and pair the destination's incoming run key with the source computer under the existing remote Trunks key settings. An already running KeepOak computer can be that destination. This does not provision or purchase a computer.

Open a saved conversation, choose its destination, and write the task to continue. Optionally include its recent conversation and latest task outcome. Branch first stops and holds the source conversation, then shows the exact selected text for review. Known secrets and familiar pasted credential forms are scrubbed; review the preview for anything else sensitive. Only the approved text is sent. Hidden memory, files, recorded tool arguments, saved credentials and settings are not copied. Historical context is marked as data, not permission to repeat past actions. The destination uses its own tools, approval rules and model budget, and can continue while the source is closed or asleep.

The dialog lists ownership transfers and offers Check progress, Retry delivery and Stop remote and return here. Cancelling an unsent preview returns ownership locally without contacting the destination. After delivery is attempted, a failed connection leaves ownership held. Retry uses the same receipt and approved context fingerprint and cannot start the same transfer twice. Returning ownership first fences the destination, cancels its tasks, waits for them to stop and confirms no managed background program remains. Only an acknowledged release lets this conversation work on the source again. No timeout or expired token silently returns ownership. If a key expires, the destination owner can pair a replacement run key with the same source computer and update that source's locker entry; the replacement can inspect and release existing transfers, while the retired pairing no longer can.

Each transfer has a durable unique receipt and an increasing conversation generation. Every runtime entry and tool call checks the fence, including descendants. Old release responses cannot unlock a newer transfer. If the destination engine restarts, interrupted transfers are not replayed automatically because the last external action may have succeeded. Review its task, return ownership, then explicitly start new work with the result you verified.

This is selected task continuation on an existing paired engine. Full transcript or encrypted memory migration, KeepOak provisioning, transparent browser/file migration and automatic replay after destination crashes are not included. The two-engine tests run isolated engines and loopback HTTP with real persistence and a real workspace write; they do not establish availability of any production KeepOak computer.
