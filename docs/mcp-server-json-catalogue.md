# Connector catalogue and registry imports

The bundled catalogue uses format 2: Branch presentation fields surround a `server` object using the official server.json package, remote and declared-input shape. Packages carry pinned versions, transport and runtime/package arguments; remotes carry declared headers and URL variables. Inputs retain `isRequired`, `isSecret`, format, choices, fixed/default values and variable declarations. Local `io.branch.catalogue/*` names and date versions identify Branch's catalogue records, not publisher attestations or the remote server's negotiated implementation version. Unverified entries contain no package or remote rather than invented launch information.

The existing read-only registry search from #956 is reused. Each query requires owner network confirmation, reaches only GET `https://registry.modelcontextprotocol.io/v0.1/servers?search=`, and retains the current network policy, refused redirects, 15-second timeout and 512 KiB response cap. Invalid/deleted results are omitted. Metadata and descriptions are escaped publisher information. No icon, package, endpoint, code or nested URL is fetched from a result.

**Fill add form** transfers validated metadata into the existing connector form. The owner chooses a published transport and fills required inputs. Adding saves both remote and package connectors off, skips package vetting/network activity during import, and never installs, spawns or connects. Switching on still uses the normal network/launch guards and existing native program approval. Existing direct API callers retain their previous add behavior unless they request `saveOff`.

The resolver supports pinned standard npm/npx and PyPI/uvx stdio packages and streamable HTTP remotes, positional/named arguments, declared environment values, variables and required/choice/number/boolean checks. Repeated arguments currently accept one value per declaration. Other registry types, SSE, custom registries and packages requiring file-hash verification stay visible but require manual configuration; import does not guess unsupported runtimes or bypass integrity requirements. Declared runtime control environment variables require manual configuration.

Private inputs accept **environment variable names**, never credential values. Argument/environment templates preserve references until authorized transport creation, and declared remote headers also use environment references with owner-selected None/Bearer/Basic prefix. Private URL substitutions are refused. Publisher secret values/defaults/placeholders/choices are stripped before display. Actual credentials are resolved only at start, supplied directly to the SDK transport, included in credential redaction, and never saved in catalogue, confirmation bytes, logs, exports or PR text. Private argument launches are checked against the workspace guard after resolution, with errors that do not echo the private value. Start failures with private bindings use a generic message. Existing launches without new bindings keep their original approval fingerprint.

Official protocol source and license were read at [registry commit bf4e88c](https://github.com/modelcontextprotocol/registry/blob/bf4e88cbe8d1a635c06144ccea1d24cb52fa6186/docs/reference/server-json/draft/server.schema.json). The schema adapter is independently implemented, with no copied implementation or new dependency. #956's existing Cline attribution and third-party notices are retained. The two bundled npm versions were checked against npm package metadata (filesystem 2026.8.31 and Playwright 0.0.83); no package was downloaded or executed.

Validation is source/diff review and `git diff --check` only. Tests, builds, app/runtime, models/providers, credential and DB operations were deferred by owner instruction. Live registry/form/SDK compatibility remains unverified.
