# Group activation and Discord threads (CHAT-123 / CHAT-124)

Settings → Chat apps → Group responses reviews exact connection/group IDs, `activation: mention|always`, and Discord-only `autoThread`. `always` means messages need no mention; pairing, sender ceilings and existing chat tool permissions are unchanged. Unknown connections and automatic threads on other transports are refused.

`/activation mention` and `/activation always` have one narrow exception to the usual ban on group owner settings: only a live account exactly named as the owner's on a vouched transport, already allowed through pairing/allowlist, in an existing known group, with App lock and Lockdown off, can change that exact group's activation. No general owner-DM commands, standing instructions or tool privileges become available from groups. Unauthorized or caught-up commands receive an explanation directing them to native Settings, and are not sent to a model as instructions.

Discord auto-thread creation happens only after router admission and sender ceiling checks. It uses `POST /channels/{channel.id}/messages/{message.id}/threads`, a bounded fixed name and archive duration, guarded existing transport, cancellation on adapter stop, a twenty-second timeout, at most two concurrent creations and a two-second start spacing. HTTP 429 or missing thread permissions fail closed and send an explanation, without starting a model task in a different destination. Thread parent ID must match the exact source channel; sender and source message remain bound. Policy and sender access are rechecked after creation. Known created threads accept follow-up messages without repeated mentions; unknown/pre-existing threads need their own configuration or normal mention activation. The in-memory known-thread map is bounded and resets on restart, so a mention may be required after restart.

Official API source reviewed: [Discord Start Thread from Message](https://github.com/discord/discord-api-docs/blob/main/developers/resources/channel.mdx#start-thread-from-message). The endpoint creates public/announcement threads on text/announcement channels; forum/media channels require different APIs and are not supported here. Discord API documentation uses CC BY-SA 4.0; this original implementation copies no documentation text or upstream code.

Delivery is source-only: no tests, builds, Discord/model calls, runtime, database or credential access. Native configuration uses an explicit JSON editor; automatic Discord slash-command picker registration for `/activation` is not added (typed commands work).
