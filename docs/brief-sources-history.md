# Morning brief sources and watch history

Stack prerequisite: WHOOP #1270, including Oura #1257. Separate price-watch #1053 already retains numeric observations, routine #1089/#1096 accounts for scheduled cost, dashboard #1106/#1116/#1117 and connector-health work are separate; this does not replace them. Integration must preserve their shared server/menu seams.

New sources default off. In the owner's unlocked private window, Morning brief & watch history lets the owner approve up to three existing search watches for news. Gathering uses bounded previously observed search titles/links, with their timestamps, stale warning and failures, through the existing injection policy. No network request is added to gathering, no publisher is claimed vetted/trusted, and no new subscription/provider is fabricated. Source selection explicitly discloses the morning brief's existing saved conversation and any configured external delivery destination. Existing watch creation/network policy/cadence and scheduler remain authoritative; news watches must already exist.

Health sources are an owner-selected review reminder in scheduled/saved/delivered text. Metrics remain separate: the same private brief view lets the owner choose a bounded date range and click an explicit private Oura/WHOOP read through their real existing APIs. Health metrics never enter MorningBrief content, persistent run messages, model tools, spoken briefs or external chats. Connector authorization, configuration identity, expiry, Lockdown and owner/profile/caller gates still apply across reads. No background health synchronization or clinical advice is implemented. The reminder is not connection proof.

Each ordinary watch retains the last 100 actual outcomes from this implementation onward. Baseline, successful unchanged checks, changes, delivery destinations/holds and failed checks are recorded. History is owner-scoped and viewable privately; pre-existing alerts are not reconstructed. A failed attempt with unacknowledged delivery is not claimed successfully delivered. Existing ten-check health status remains independent. Watch removal deletes its retained history. Database migration code is additive but was not executed during delivery.

Source reviewed: [Hermes product price monitor recipe](https://github.com/NousResearch/hermes-agent/blob/7327624d3500d4bbc9ad58b0a75c324a306d882a/skills/productivity/product-price-monitor/SKILL.md) and [MIT license](https://github.com/NousResearch/hermes-agent/blob/7327624d3500d4bbc9ad58b0a75c324a306d882a/LICENSE). Its distinction between failed observation, known baseline and acknowledged alerts informed source review. No upstream code was copied; implementation uses Branch's deterministic monitor/brief protocol without new dependencies.

Source review and diff checks only. No tests, build, provider/news/auth/model calls, database/app execution or installations were performed. Live behavior and integration acceptance remain unverified. Scheduled health metrics and new news subscriptions are intentionally unsupported; provider costs/terms remain those disclosed by the existing connectors.
